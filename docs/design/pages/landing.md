# Landing Page Override

This page follows the SkillBridge master system with the following page-specific rules.

## Objective

Explain the product clearly enough that a student, business, university reviewer, or competition judge understands the proof-to-payout loop without using a demo fixture.

## Section order

1. Hero with product promise and a static proof-route visual.
2. Four trust signals: human decision, hashed evidence, Devnet verification, direct USDC.
3. Three-sided market problem.
4. Five-step Proof-to-Payout workflow.
5. Three grouped product capabilities.
6. Role-specific value for students, businesses, and universities.
7. Light trust architecture.
8. Vietnam-first pilot CTA and legal footer.

## Page rules

- The first viewport must contain the promise, primary wallet CTA, and recognizable product proof surface.
- Keep the language switcher in the upper-right action group.
- No Demo navigation item or interactive demo fixture on the landing page.
- Do not show invented scores, transaction amounts, partners, users, or testimonials.
- Use lime only for primary conversion and positive/approved outcomes.
- Use violet for protocol and verification cues.
- Keep the experience fully light-terminal; use ink as text/border, not as a full-section background.
- Mobile collapses workflow horizontally into a vertical rail with no content loss.
